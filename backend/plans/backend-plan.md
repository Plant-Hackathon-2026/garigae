## 한 줄 요약

이미지를 올리면 EasyOCR로 글자를 읽고, 그중 민감정보 위치를 찾아 블러 처리한다. 사용자가 감지 결과를 확인·수정한 뒤 적용하는 흐름이고, 서버는 이미지를 저장하지 않는다.

## 인터뷰로 정한 사항

| 항목 | 결정 |
|---|---|
| 대상 이미지 | 신분증·카드, 화면 캡처, 문서·영수증·택배 송장, 일반 사진 전부 |
| 감지 항목 | 식별번호(주민·외국인등록번호, 여권, 운전면허), 연락처(전화, 이메일), 금융정보(카드, 계좌), 이름·주소 |
| 비텍스트(얼굴, QR) | 다루지 않음. 글자만 처리 |
| 처리 흐름 | 감지 → 사용자 확인 → 적용의 2단계. 바로 가린 결과를 주는 원샷 API도 함께 제공 |
| 이름·주소 감지 | 백엔드는 규칙 기반으로 먼저 구현. NER은 다른 팀원이 만들어서 같은 레포에 감지기 모듈로 추가하고, 두 결과를 합침 |
| 외부 LLM API | 쓰지 않음. 민감정보가 서버 밖으로 나가면 서비스 취지와 맞지 않음 |
| 이미지 저장 | 저장하지 않음. 적용 단계에서 프론트가 원본과 영역 목록을 다시 보냄 |
| 가림 범위 | 감지된 문자열 영역을 통째로 가림 (부분 가림 안 함) |
| 배포 | 대회 측이 제공할 GPU 서버. 사양(CUDA 버전, Docker 가능 여부)은 아직 모름 |
| 로컬 테스트 | 현재 Mac(Apple Silicon) |

## AI가 맡는 부분

"AI가 찾고, 규칙이 검증하고, 사람이 확인한다"는 구조다.

| 단계 | 방식 | 하는 일 | 담당 |
|---|---|---|---|
| 글자 인식 | AI: EasyOCR (글자 영역 검출 CRAFT + 글자 인식 CRNN) | 이미지에서 글자 위치와 내용을 추출. 기울어짐, 조명, 글꼴이 달라도 읽음 | 백엔드 |
| 이름·주소 판단 | AI: 한국어 NER 모델 | 문맥을 보고 사람 이름과 주소를 구분. 라벨 없이 쓰인 이름도 찾음 | NER 담당자 |
| 형식이 정해진 정보 | 규칙: 정규식 + 검증 | 주민번호, 전화번호, 카드번호 등. 형식이 정해져 있어 규칙이 더 정확하고 판정 이유를 설명할 수 있음 | 백엔드 |
| 이름·주소 보조 | 규칙: 라벨·주소 패턴 | NER이 늦어지거나 놓친 경우를 대비 | 백엔드 |
| 최종 확인 | 사람 | 놓친 부분 추가, 오탐 해제 | 사용자(프론트) |

- AI 모델은 모두 서버 안에서 돈다. 외부 API를 쓰지 않으므로 민감정보가 밖으로 나가지 않는다
- 심사에서 "AI가 뭘 하나요?"라는 질문이 나오면: 정형화되지 않은 이미지에서 글자를 읽는 것(OCR)과 문맥으로 이름·주소를 판단하는 것(NER)이 AI이고, 형식이 정해진 번호는 규칙으로 검증해서 정확도와 설명 가능성을 챙겼다고 답한다

### 확장 후보: 로컬 LLM 재판정 (도입 여부 미정)

규칙이나 NER이 애매하게 잡은 후보를 GPU 서버 안의 소형 LLM에 앞뒤 줄과 함께 보내 다시 판정하게 하는 방식이다.

- 예: 송장의 `1234-56-789012`가 계좌번호인지 주문번호인지, 두세 글자 한글이 이름인지 일반 단어인지
- 장점: 문맥 판단이 늘어 AI 비중이 커지고 오탐이 준다. 서버 안에서 돌아서 외부 전송이 없다
- 부담: GPU 메모리(7B급 모델을 4비트로 줄여도 5~6GB 정도, EasyOCR와 같이 올려야 함), 응답 지연, NER 역할과 일부 겹침, 백엔드 1인 일정
- 넣는다면 CP2 이후 Could로 진행한다

## 처리 흐름

```
업로드 이미지
  ↓ image_io: 형식·크기 검사, EXIF 방향 보정
  ↓ ocr: EasyOCR readtext → 글자 박스(segment) 목록
  ↓ lines: 같은 줄의 박스를 묶어 줄 텍스트로 재구성 (문자 위치 ↔ 박스 매핑 유지)
  ↓ detectors: regex / rules / ner 감지기가 각각 "줄 + 문자 구간 + 항목 종류" 반환
  ↓ merge: 겹치는 구간 합치기 (겹치면 넓게)
  ↓ geometry: 문자 구간 → 이미지 좌표 다각형 (부분 문자열이면 박스 안에서 위치 추정 + 여백)
  ↓
/api/detect  → 감지 결과 JSON
/api/redact  → 프론트가 보낸 영역에 블러 적용 → 이미지 (메타데이터 제거)
```

### 핵심 처리 1: 줄 단위 재구성

EasyOCR는 띄어쓰기나 간격에 따라 `010 1234 5678`을 박스 여러 개로 쪼갤 수 있다. 박스 하나씩 정규식을 돌리면 놓친다.

- 글자 방향(박스 기울기)이 비슷하고, 그 방향에 수직인 축으로 위치가 겹치는 박스를 한 줄로 묶는다. 줄 안에서는 글자 방향을 따라 정렬해 공백으로 이어 붙인다.
- 세로 위치만으로 묶으면 안 된다. EasyOCR는 약 5.7° 이상 기울어진 박스를 옆 박스와 합치지 않고 따로 주는데, 기울어진 줄에서는 단어마다 세로 위치가 달라서 한 줄로 묶이지 않는다.
- 줄 텍스트의 문자 위치마다 "몇 번째 박스의 몇 번째 문자인지"를 기록해 둔다.
- 감지기는 줄 텍스트만 보고, 위치 복원은 geometry가 맡는다. 감지기 구현자(NER 담당자 포함)는 좌표를 몰라도 된다.

### 핵심 처리 2: 부분 문자열 좌표 추정

`연락처: 010-1234-5678`이 박스 하나로 나오면 번호 부분만 가려야 한다.

- 문자 종류별 폭 가중치로 위치를 추정한다: 한글·한자 1.0, 영문·숫자 0.6, 공백 0.35, 구두점 0.4 (샘플로 보정).
- 기울어진 박스도 처리하도록 다각형의 위·아래 변을 같은 비율로 잘라서 보간한다. 잘린 영역도 기울기가 유지된다.
- 추정 오차를 감안해 앞뒤로 글자 반 칸, 위아래로 높이의 10% 여백을 둔다. **덜 가리는 것보다 더 가리는 쪽**으로 맞춘다.
- 한 항목이 박스 여러 개에 걸치면 전체를 감싸는 최소 회전 직사각형(`cv2.minAreaRect`) 하나로 합친다. 그래서 응답의 다각형은 항상 꼭짓점 4개다.

EasyOCR가 주는 박스 모양 (1.7.2 소스 확인):

- 글자 영역을 감싸는 최소 회전 직사각형(`cv2.minAreaRect`)으로 만든다. 사다리꼴이나 자유로운 사각형은 나오지 않는다
- 위·아래 변 기울기가 0.1(약 5.7°) 미만이면 수평 직사각형으로 바꾼다. 그 이상이면 회전 직사각형을 대각선 방향으로 조금 넓혀서 준다. 이 계산 때문에 꼭짓점이 정확한 직사각형에서 1~2픽셀 어긋날 수 있다
- 비스듬히 찍어 원근이 생긴 글자도 그 글자를 감싸는 회전 직사각형으로 나온다. 그만큼 주변이 조금 더 가려진다
- 꼭짓점 순서는 x+y가 가장 작은 점부터 시계 방향이다. 45° 넘게 기울면 첫 점이 글자 기준 왼쪽 위가 아니므로, 내부 계산에서는 긴 변을 글자 방향으로 보고 순서를 다시 정한다

### 핵심 처리 3: OCR 오인식 보정

숫자 문맥에서 자주 틀리는 글자를 길이를 유지한 채 바꾼 사본에 정규식을 돌린다. 길이가 같아서 문자 위치는 그대로 원본에 쓸 수 있다.

- `O`, `o` → `0` / `l`, `I`, `|` → `1` / `—`, `–`, `一`, `~` → `-` (숫자 사이에 있을 때만)

### 핵심 처리 4: 돌아간 이미지

EXIF 정보 없이 이미지 자체가 90°·180° 돌아가 있으면 EasyOCR 기본 설정으로는 글자를 거의 못 읽는다.

- EasyOCR의 `rotation_info=[90, 180, 270]`을 쓰면 글자 조각을 돌려 가며 읽고 가장 잘 읽힌 결과를 고른다. 좌표는 원본 이미지 기준 그대로다
- 글자 인식을 회전 수만큼 더 돌리므로 느려진다. 환경변수 `GARIGAE_OCR_ROTATIONS`로 켜고 끌 수 있게 하고, 배포 서버에서 처리 시간을 잰 뒤 기본값을 정한다

## 감지 규칙

### 정규식 감지기 (`regex`)

| 종류 (`type`) | 패턴 요약 | 추가 검증 | 오탐 방지 |
|---|---|---|---|
| 주민등록번호 `resident_id` | `YYMMDD` + 구분자(`-`, 공백, 없음) + `[1-4]` + 6자리 | 앞 6자리 날짜 유효성 (2020년 10월 이후 번호는 검증숫자 규칙이 없어 체크섬은 안 봄) | 앞뒤가 숫자로 이어지면 제외 |
| 외국인등록번호 `foreigner_id` | 위와 같고 뒷자리 첫 숫자 `[5-8]` | 날짜 유효성 | 같음 |
| 여권번호 `passport` | `[MSRODG]` + 8자리(구형), `[MSRODG]` + 3자리 + 영문 + 4자리(차세대) | | "여권", "Passport" 근처면 신뢰도 높임 |
| 운전면허번호 `driver_license` | `NN-NN-NNNNNN-NN`, 구형 `서울 NN-NNNNNN-NN` | 지역 코드 범위 | |
| 전화번호 `phone` | 휴대폰 `01[016789]`, 유선 `02`·`0[3-6][1-5]`, `070`, 안심번호 `050X` | 자릿수 | 대표번호 `15XX`·`16XX`·`18XX`는 개인정보가 아니라 제외 |
| 이메일 `email` | 일반 이메일 형식 | | |
| 카드번호 `card` | 4-4-4-4, 아멕스 4-6-5. 영수증의 `1234-56**-****-7890`처럼 일부 가려진 형태도 포함 | Luhn (가려진 형태는 생략) | 앞뒤 숫자 경계 |
| 계좌번호 `account` | 숫자 10~14자리, 하이픈 그룹 2개 이상 | | **같은 줄이나 바로 윗줄에 은행명·"계좌"·"입금"·"예금주"가 있을 때만** 감지 (주문번호·송장번호 오탐이 많아서) |

### 규칙 감지기 (`rules`): 이름·주소

NER이 들어오기 전에도 데모가 되도록 백엔드가 직접 만든다. 정규식보다 신뢰도를 낮게 매기고, 확인 단계에서 사용자가 걸러낸다.

- **라벨 기반 이름**: `성명`, `이름`, `받는 분`, `보내는 분`, `수령인`, `수취인`, `예금주`, `고객명`, `신청인`, `Name` 뒤의 한글 2~4자(또는 영문 이름). 라벨만 있는 박스면 오른쪽 박스나 바로 아랫줄 첫 박스를 값으로 본다. `홍*동`처럼 일부 가려진 이름도 포함
- **라벨 기반 주소**: `주소`, `주 소`, `거주지`, `배송지`, `받는 곳`, `Address` 뒤부터 줄 끝까지. 다음 줄도 주소 형태면 이어서 포함
- **패턴 기반 주소**: 시·도명 + 시·군·구 + (`로`|`길`|`동`|`읍`|`면`|`리`) + 번지 숫자
- (Should) **신분증 이름**: `주민등록증`, `운전면허증` 문구가 있는 이미지에서, 상단의 단독 한글 2~4자 줄이 성씨 사전에 맞으면 이름으로 본다

### NER 감지기 (`ner`): 다른 팀원 담당

아래 인터페이스를 백엔드가 먼저 만들어 main에 넣고, NER 담당자는 `detectors/ner.py`만 구현하면 되게 한다.

```python
# backend/src/backend/detectors/base.py
class TextLine(BaseModel):
    id: int
    text: str            # 줄 단위로 재구성된 OCR 텍스트

class PiiSpan(BaseModel):
    line_id: int
    start: int           # text 기준 문자 위치 (start 포함, end 미포함)
    end: int
    type: PiiType        # name, address 등
    score: float         # 0~1
    source: str          # "ner"

class Detector(Protocol):
    name: str
    def detect(self, lines: Sequence[TextLine]) -> list[PiiSpan]: ...
```

NER 담당자와 맞출 약속:

- 모델 로딩은 `__init__`에서 한 번만 한다(서버 시작 시 호출). 요청마다 로딩하지 않는다
- 외부 네트워크를 호출하지 않는다. 모델 파일은 미리 받아 두거나 시작 시 한 번만 받는다
- 의존성(transformers 등)은 `pyproject.toml`의 optional 그룹 `ner`에 넣어서, NER 없이도 서버가 뜨게 한다
- 켜고 끄기는 환경변수 `GARIGAE_DETECTORS=regex,rules,ner`
- 백엔드가 제공하는 것: 스텁(`[]` 반환), 샘플 `TextLine` 목록, 감지기 단위 테스트 틀

## API

모든 좌표는 **EXIF 방향 보정 후 원본 이미지 픽셀 기준**이다. 브라우저도 EXIF 방향을 적용해서 보여주므로 프론트는 `image.width`, `image.height`로 화면 크기에 맞게 비율만 맞추면 된다.

영역은 **`polygon` 하나로만** 주고받는다. 수평 사각형(`bbox`)은 따로 주지 않는다.

- `polygon`: `[[x, y], ...]` 꼭짓점 4개, 시계 방향. 대부분 회전된 직사각형이고, 기울기가 약 5.7° 미만이면 수평 직사각형이다 (모양은 "핵심 처리 2" 참고)
- `bbox`를 빼는 이유: 기울어진 글자를 `bbox`로 가리면 위아래 다른 글자까지 가려진다. 가릴 영역의 정답은 `polygon`이므로 하나로 통일해서 잘못 쓸 여지를 없앤다. 사각형이 필요하면 x·y의 최솟값·최댓값으로 바로 계산할 수 있다
- 프론트는 직사각형이라고 가정하고 각도를 계산하지 말고 꼭짓점을 그대로 이어 그린다. 이미지 위에 SVG를 겹치고 `viewBox="0 0 {image.width} {image.height}"`로 두면 화면 크기가 달라도 좌표를 변환할 필요가 없다

```tsx
<div style={{ position: "relative" }}>
  <img src={imageUrl} style={{ width: "100%", display: "block" }} />
  <svg
    viewBox={`0 0 ${image.width} ${image.height}`}
    style={{ position: "absolute", inset: 0, width: "100%", height: "100%" }}
  >
    {detections.map((d) => (
      <polygon key={d.id} points={d.polygon.map((p) => p.join(",")).join(" ")} onClick={() => toggle(d.id)} />
    ))}
  </svg>
</div>
```

### `POST /api/detect`

- 요청: `multipart/form-data`, `file` (JPEG/PNG/WEBP, 최대 10MB)
- 응답:

```json
{
  "image": { "width": 1280, "height": 960, "format": "jpeg" },
  "detections": [
    {
      "id": "d1",
      "type": "phone",
      "label": "전화번호",
      "text": "010-0000-0000",
      "polygon": [[412, 233], [580, 233], [580, 261], [412, 261]],
      "confidence": 0.93,
      "source": "regex"
    }
  ],
  "text_regions": [
    {
      "id": "t1",
      "text": "연락처: 010-0000-0000",
      "polygon": [[340, 231], [584, 231], [584, 263], [340, 263]],
      "confidence": 0.95
    }
  ],
  "elapsed_ms": 820
}
```

- `detections`: 민감정보로 감지된 영역. 프론트가 기본으로 켜 둔 상태로 보여줌
- `text_regions`: OCR이 읽은 모든 글자 박스. 감지가 놓친 부분을 사용자가 눌러서 추가로 가릴 수 있게 함
- `confidence`: OCR 신뢰도 × 감지기 점수

### `POST /api/redact`

- 요청: `multipart/form-data`
  - `file`: 원본 이미지 (서버가 저장하지 않으므로 다시 보냄)
  - `regions`: JSON 문자열. 가릴 영역의 `polygon` 목록. 감지 결과와 `text_regions`의 `polygon`은 그대로 보내고, 사용자가 직접 그린 사각형은 프론트가 꼭짓점 4개 `[[x, y], [x+w, y], [x+w, y+h], [x, y+h]]`로 바꿔서 보낸다

    ```json
    [{ "polygon": [[412, 233], [580, 233], [580, 261], [412, 261]] },
     { "polygon": [[100, 50], [180, 50], [180, 80], [100, 80]] }]
    ```

  - `mode`: `blur`(기본) | `pixelate` | `box`
- 응답: 가린 이미지 바이너리. 입력과 같은 형식(PNG→PNG, JPEG→JPEG 품질 95), **EXIF 등 메타데이터 전부 제거**

### `POST /api/redact/auto`

- 요청: `file`, `mode`, `types`(선택, 쉼표 구분. 생략하면 전체)
- 응답: 감지된 영역을 전부 가린 이미지. 데모와 빠른 확인용

### 기타

- `GET /api/health`: `{"status": "healthy", "ocr_ready": true, "device": "cuda"}`
- `GET /api/pii-types`: 항목 종류와 한국어 라벨 목록 (프론트 필터 UI용, Should)

### 오류

| 코드 | 경우 |
|---|---|
| 400 | 이미지를 열 수 없음, `regions` 형식 오류 (꼭짓점이 4개가 아님 등). 이미지 밖 좌표는 오류 대신 이미지 경계로 잘라서 처리 |
| 413 | 10MB 초과, 또는 픽셀 수 초과(압축 폭탄 방지, 약 4천만 픽셀) |
| 415 | JPEG/PNG/WEBP가 아님 (확장자가 아니라 실제 파일 내용으로 판단) |
| 503 | OCR 모델 로딩 전 |

## 개인정보 처리 원칙

발표에서 강조할 수 있는 부분이라 구현 단계부터 지킨다.

- 업로드 이미지와 OCR 텍스트는 요청 처리 중 메모리에만 있고, 디스크나 DB에 저장하지 않는다
- 로그에 이미지 내용, OCR 텍스트, 감지된 문자열을 남기지 않는다. 남기는 건 처리 시간, 이미지 크기, 감지 개수 같은 통계뿐
- 외부 API를 호출하지 않는다. OCR과 감지가 모두 서버 안에서 끝난다
- 결과 이미지에서 EXIF를 지운다. 사진의 GPS 위치도 민감정보다
- 블러는 커널 크기를 글자 높이(다각형의 짧은 변) 이상으로 잡아 복원을 어렵게 한다. 기울어진 글자는 수평 외접 사각형의 높이가 실제 글자보다 크므로 그 값을 쓰지 않는다. 가장 확실한 방법이 필요하면 `box` 모드를 쓴다

    test_regex.py        # 항목별 맞아야 하는 예 / 틀려야 하는 예 표
    test_rules.py
    test_lines.py
    test_geometry.py
    test_masking.py      # 영역 안만 바뀌고 밖은 그대로인지
    test_api.py          # 가짜 OCR 엔진으로 엔드포인트 검사

- 테스트에서는 `OcrEngine`을 가짜로 바꿔 끼워서 torch 없이 빠르게 돌린다

## 샘플 데이터

- **실제 개인정보는 쓰지 않는다.** 이름, 번호, 주소 모두 가짜로 만든다
- `scripts/make_samples.py`로 Pillow + 한글 폰트를 써서 신분증 형태, 택배 송장, 메신저 캡처, 영수증, 계좌 안내문 이미지를 만든다. 정답 영역도 같이 저장한다
- 일반 사진 유형은 가짜 정보를 출력하거나 화면에 띄운 뒤 직접 촬영해서 몇 장 추가한다(기울어짐, 조명 변화 확인용)
- `scripts/evaluate.py`로 항목별 재현율을 내서 튜닝 근거와 발표 자료로 쓴다

## 배포

GPU 서버 사양을 아직 모르므로 두 경로를 준비한다.

1. **Docker** (기본): `python:3.11-slim` + uv. PyPI torch 휠에 CUDA 런타임이 들어 있어서 CUDA 베이스 이미지는 필요 없고, 서버에 NVIDIA 드라이버와 nvidia-container-toolkit만 있으면 된다. `docker run --gpus all`. EasyOCR 모델은 빌드할 때 미리 받아 이미지에 넣는다
2. **직접 실행** (Docker를 못 쓸 때): 서버에서 `uv sync && uv run uvicorn backend.main:app --host 0.0.0.0`

서버를 받으면 바로 확인할 것:

- `nvidia-smi`로 드라이버 버전 확인 → 설치될 torch의 CUDA 버전을 지원하는지. 드라이버가 오래됐으면 `[tool.uv.sources]`에서 Linux일 때만 PyTorch 공식 인덱스(예: `cu121`)를 쓰도록 고정
- 외부 접속 포트, HTTPS 필요 여부, 프론트 도메인 → CORS 허용 목록(`GARIGAE_CORS_ORIGINS`)에 추가

서버가 늦게 나오거나 문제가 생기면 이 Mac에서 백엔드를 띄워 데모한다.

## 범위

시간이 밀리면 Could부터 자른다.

- **Must**
  - EasyOCR(한국어+영어) 연동, 서버 시작 시 모델 로딩
  - 줄 재구성 + 부분 문자열 좌표 추정
  - 정규식 감지기: 식별번호, 연락처, 금융정보 (검증 로직 포함)
  - 블러 마스킹
  - `/api/detect`, `/api/redact`, `/api/redact/auto`
  - 이미지 무저장, EXIF 방향 보정·제거, 파일 검사
  - NER 감지기 인터페이스 + 스텁
  - 가짜 샘플 이미지, 감지기 단위 테스트
- **Should**
  - 이름·주소 규칙 감지기
  - `pixelate`, `box` 모드
  - `text_regions` 응답, `/api/pii-types`
  - OCR 오인식 보정
  - 돌아간 이미지 인식 (`rotation_info`)
  - 평가 스크립트와 재현율 수치
  - GPU 서버 Docker 배포
- **Could**
  - 신분증 이름 휴리스틱
  - 로컬 LLM 재판정 (도입 여부 미정, "AI가 맡는 부분" 참고)
  - HEIC(아이폰 사진) 지원
  - 여러 장 한 번에 처리
  - PDF 입력
- **Won't**
  - 얼굴, QR·바코드 가리기
  - 외부 LLM API
  - 이미지 저장, 처리 이력, 사용자 계정
  - 부분 가림

## 타임라인

계획 확정 시점을 H+0으로 둔다.

| 시간 | 할 일 |
|---|---|
| H+0~1 | 브랜치 생성, 의존성 추가, EasyOCR 모델 받기(대회장 네트워크 대비), Mac에서 MPS로 샘플 한 장 OCR 확인 |
| H+1~3 | 데이터 모델·감지기 인터페이스·API 스키마 작성. **프론트에 API 계약(위 JSON 예시) 전달, NER 담당자에게 인터페이스와 스텁 전달** |
| H+3~5 | 끝까지 한 번 흐르게 연결: OCR → 줄 재구성 → 전화번호 정규식 하나 → 블러 → `/api/redact/auto` |
| **H+5** | **CP1: 전화번호가 있는 샘플 이미지를 올리면 번호만 가려진 이미지가 돌아온다** |
| H+5~10 | 정규식 전체 항목 + 검증, 부분 좌표 추정 다듬기, `/api/detect`·`/api/redact`, 오류 처리, 샘플 이미지 생성 |
| **H+10** | **CP2: 프론트와 연동해서 감지 → 확인 → 적용이 화면에서 돈다** |
| H+10~14 | 이름·주소 규칙, NER 구현 병합, 평가 스크립트로 튜닝 |
| H+14~17 | GPU 서버 배포, 처리 시간 측정, 워밍업 |
| **H+17** | **CP3: 배포 서버에서 프론트와 연결된 데모가 돈다** |
| H+17~20 | 기능 동결, 버그 수정, 데모용 샘플 정리, 리허설 지원 |
| H+20~ | 발표 준비: 백엔드 설명, 예상 질문 답변 |

- NER 병합 마감은 H+14. 그때까지 안 들어오면 규칙 기반만으로 데모한다
- GPU 서버가 H+14까지 안 나오면 Mac 로컬 데모로 진행하고 서버 배포는 나오는 대로 한다

## 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 작은 글씨, 저해상도 캡처에서 OCR이 못 읽음 | `mag_ratio`로 확대해서 읽기. 그래도 놓치면 확인 단계에서 사용자가 `text_regions`나 직접 그린 사각형으로 보완 |
| 숫자가 박스 여러 개로 쪼개짐 | 줄 단위 재구성 후 정규식 적용 |
| `O`↔`0`, `-`↔`一` 같은 오인식 | 길이 유지 치환으로 보정 |
| 부분 문자열 위치가 어긋나 일부가 덜 가려짐 | 문자 폭 가중치 + 여백. 덜 가리는 것보다 더 가리는 쪽으로 |
| 기울어진 줄이 한 줄로 묶이지 않음 | 세로 위치가 아니라 글자 방향 기준으로 줄 재구성 |
| 이미지가 90°·180° 돌아가 있어 글자를 못 읽음 | `rotation_info` 옵션. 처리 시간을 보고 기본값 결정 |
| 계좌번호·이름 오탐 | 계좌는 키워드가 있을 때만, 이름은 라벨이 있을 때만. 남은 오탐은 확인 단계에서 해제 |
| Mac MPS에서 일부 연산 오류 | `PYTORCH_ENABLE_MPS_FALLBACK=1`, 그래도 안 되면 `GARIGAE_OCR_DEVICE=cpu` |
| 대회장 네트워크에서 모델 다운로드 실패 | 지금 미리 받아 두고, Docker 이미지에 포함 |
| GPU 서버 지연, 드라이버·CUDA 불일치 | Docker와 직접 실행 두 경로, torch 인덱스 고정, Mac 로컬 데모로 대체 |
| NER 병합 지연, 의존성 충돌 | optional 그룹으로 분리, H+14 마감 후에는 규칙 기반만 사용 |
| 큰 이미지로 메모리 초과·지연 | 10MB·픽셀 수 제한, OCR 락으로 동시 추론 1개 |

## 발표에서 쓸 백엔드 포인트

- **서버에 남는 게 없다**: 이미지와 텍스트를 저장하지 않고, 외부로 보내지 않는다. 결과 이미지의 GPS 같은 메타데이터도 지운다
- **오탐을 줄이는 검증**: 주민번호 날짜 검사, 카드번호 Luhn 검사, 계좌번호 키워드 조건
- **사람이 마지막에 확인**: OCR이 놓치거나 잘못 잡은 부분을 사용자가 바로잡는다
- **수치**: 가짜 샘플 세트 기준 항목별 재현율

### 예상 질문

- **OCR이 놓치면 어떻게 하나요?** 확인 단계에서 OCR이 읽은 모든 글자 박스를 보여주고, 직접 영역을 그려서 가릴 수도 있다
- **블러는 복원되지 않나요?** 글자 높이 이상의 커널로 강하게 처리하고, 확실하게 지우려면 검은 박스 모드를 쓴다
- **왜 LLM을 안 썼나요?** 민감정보를 가리려는 서비스가 그 정보를 외부 API로 보내면 안 되기 때문이다. NER도 서버 안에서 돈다
- **얼굴은요?** 이번 범위는 글자다. 얼굴 검출 모델을 같은 감지기 구조에 추가하면 된다

## 실행·검증 방법

```bash
cd backend
uv sync
uv run uvicorn backend.main:app --reload     # http://localhost:8000/docs
uv run pytest -m "not ocr"                   # 빠른 테스트
uv run pytest -m ocr                         # 실제 EasyOCR 포함
uv run python scripts/evaluate.py            # 샘플 세트 재현율
```
